# data-commit: 데이터 분석 조직 커밋 스킬

변경 사항을 읽고 → 목적이 같은 파일끼리 묶고 → 컨벤션에 맞는 메시지를 만들어 → 사용자 확인 후 커밋한다.

분석 조직의 저장소에서는 코드·데이터·노트북·결과물(그림, 리포트)이 한꺼번에 바뀌는 일이 흔하다. 한 커밋에 섞이면 "이 수치가 왜 바뀌었는지" 추적이 불가능해지므로, **커밋 하나 = 되돌리거나 설명할 수 있는 의미 단위 하나**로 쪼개는 것이 이 스킬의 핵심이다.

## 커밋 메시지 형식

```
<type>(<scope>): <제목>

<본문 - 선택>

<푸터 - 선택>
```

- **type**: 아래 표에서 선택 (소문자). 판단이 어려우면 `references/data-conventions.md`의 판별 규칙 참고.
- **scope**: 선택. 변경된 분석 대상·도메인 명사 (`bus`, `alighting`, `routes`, `stops` 등). 한 커밋이 여러 도메인에 걸치면 생략.
- **제목**: 한국어, 50자 내외, 마침표 없이 명사형/개조식으로 끝맺는다 (예: "노선별 하차 집계 추가"). 이 저장소 기존 이력은 "~했습니다."체를 쓰지만, 제목은 짧게 유지하기 위해 개조식을 권장한다. 사용자가 기존 문체를 원하면 그것을 따른다.
- **본문**: "무엇을"보다 **"왜"와 영향**을 쓴다. 분석 변경이라면 기준(기간·필터·집계 단위)과 결과 수치 변화를 적는다. 자명한 변경이면 생략.
- **푸터**: `Refs: #12`, `BREAKING CHANGE: ...` 등. 산출물 스키마·컬럼명이 바뀌어 하위 분석이 깨지면 `!` 또는 `BREAKING CHANGE`로 알린다.

> 참고: 기존 이력은 `feat : 설명`처럼 콜론 앞에 공백이 있다. 이 스킬은 도구 호환(changelog, commitlint)을 위해 Conventional Commits 표준인 `type: 제목`(공백 없음)을 쓴다.

## 타입

| type | 쓰는 경우 | 대표 경로/파일 |
|---|---|---|
| `feat` | 새 분석·지표·기능·스크립트 추가 | `*.py`, `src/` |
| `fix` | 오류·잘못된 집계/조인/필터 수정 | `*.py`, `*.sql` |
| `data` | 원천·더미·참조 데이터 추가/갱신/삭제 | `data/`, `*.csv`, `*.xlsx`, `*.parquet` |
| `analysis` | 탐색적 분석(EDA)·노트북·분석 결과 문서 | `*.ipynb`, `notebooks/`, `out_*.md` |
| `viz` | 차트·지도·대시보드·리포트 시각화 | `fig/`, `*.png`, `viz_*.py` |
| `pipeline` | ETL·수집·스케줄·전처리 흐름 변경 | `etl/`, `dags/`, `make_*.py` |
| `model` | 피처·모델 학습/튜닝/평가 | `models/`, `features/` |
| `refactor` | 결과 불변인 코드 구조 개선 | `*.py` |
| `perf` | 속도·메모리 개선 (결과 불변) | `*.py`, `*.sql` |
| `test` | 데이터 검증·단위 테스트 | `tests/` |
| `docs` | README·데이터 사전·주석 | `*.md`, `docs/` |
| `build` | 의존성·환경 (requirements, conda, Dockerfile) | `requirements.txt` |
| `chore` | 위에 안 들어가는 잡무 (`.gitignore`, 설정) | `.gitignore` |
| `revert` | 이전 커밋 되돌림 (본문에 되돌린 해시) | |

`feat`/`fix`는 "결과나 동작이 달라지는" 변경, `refactor`/`perf`는 "결과가 같은" 변경이다. 이 구분이 분석 재현성의 기준이 되므로, 코드를 고치면서 결과 수치가 바뀌면 `refactor`가 아니라 `fix`/`feat`로 쓰고 본문에 수치 변화를 남긴다.

## 작업 절차

1. **현황 파악** — 아래를 실행한다. 이미 staged된 파일이 있으면 사용자 의도이므로 존중한다 (그것만 커밋할지 확인).
   ```powershell
   git status --short
   git diff --stat
   git diff            # 필요 시 파일별로 (대용량 데이터/노트북은 --stat만)
   git log --oneline -n 10   # 기존 문체·scope 관례 확인
   ```
   untracked 파일은 내용을 직접 열어 목적을 파악한다.

2. **안전 점검** — 커밋 대상에서 제외하고 사용자에게 알린다: `.env`, 키/토큰/비밀번호가 든 파일, 개인정보(이름·전화·주민번호 등)가 든 원본 데이터, 대용량 바이너리(수십 MB↑), `.ipynb_checkpoints`, `__pycache__`, 임시 엑셀(`~$*.xlsx`). `.gitignore`에 추가가 필요하면 `chore` 커밋으로 별도 제안한다.

3. **분류와 묶기** — 각 파일의 변경 목적을 파악해 그룹을 만든다. 묶는 기준:
   - **같은 목적이면 한 그룹**: 분석 스크립트 + 그 스크립트가 만든 `out_*.md`/그림은 보통 같이 간다 (산출물은 생성한 코드와 함께 커밋해야 추적된다).
   - **데이터와 코드는 분리**: 데이터 파일 변경(`data`)은 코드 변경과 따로 커밋한다. 데이터 때문에 코드가 바뀐 것이라도, 데이터를 먼저 커밋하고 코드를 뒤에 커밋하면 이력이 읽기 쉽다.
   - **문서·설정은 분리**: README, `.gitignore`, 의존성은 각각 독립 커밋.
   - **노트북**: 출력(output)만 달라진 변경은 코드 변경과 섞지 말고, 가능하면 제안만 하고(출력 제거 후 커밋 권장) 사용자에게 맡긴다.
   - **한 파일 안에 성격이 다른 변경**이 섞여 있으면 `git add -p`로 쪼개는 방안을 제안한다. 단, 대화형 명령은 직접 실행할 수 없으므로 사용자에게 안내하거나 한 커밋으로 합치는 선택지를 준다.
   - 억지로 쪼개지 않는다. 파일이 1~2개이거나 목적이 하나면 커밋 하나로 충분하다.
   - 순서는 의존 관계를 따른다 (build → data → pipeline → feat/fix → analysis → viz → docs 순이 기본).

4. **계획 제시 (커밋 전 확인)** — 아래 형태로 보여주고 사용자 승인을 받는다. 커밋은 되돌리기 번거롭고 이력에 남으므로, 승인 없이 실행하지 않는다.
   ```
   [1] data(bus): 노선·하차 더미 데이터 생성 스크립트와 결과 추가
       - make_dummy_data.py
       - data/routes.xlsx
       - data/alighting.xlsx
   [2] feat(bus): pandas 데이터 읽기 스크립트 추가
       - read_bus_data.py
   제외: ~$routes.xlsx (임시 파일)
   ```
   각 그룹의 근거를 한 줄로 덧붙이면 사용자가 수정하기 쉽다.

5. **커밋 실행** — 승인 후 그룹마다 순서대로 실행한다. 한글이 깨지지 않도록 메시지를 임시 파일(UTF-8)에 쓰고 `-F`로 넘긴다 (PowerShell 5.1에서 `-m` 인자의 한글은 코드페이지 문제가 생길 수 있다). 임시 파일은 scratchpad에 둔다.
   ```powershell
   git add -- <그룹의 파일들>
   git commit -F <메시지파일경로>
   ```
   `git add .`/`-A`는 쓰지 않는다 — 제외하기로 한 파일이 딸려 들어간다. 훅이 실패하면 `--no-verify`로 우회하지 말고 원인을 고친 뒤 새 커밋을 만든다.

6. **마무리** — `git log --oneline -n <그룹 수>`로 결과를 보여준다. push는 요청이 있을 때만 한다.

## 메시지 예시

```
data(bus): 노선·하차 더미 데이터 생성 스크립트 추가

seed 고정(42)으로 재현 가능하게 생성. routes 120행, alighting 3만 행.
```

```
fix(stops): 정류장별 하차 집계 시 중복 노선 이중 집계 수정

노선-정류장 조인에서 route_id 중복이 있어 상위 10개 합계가 약 8% 과대 집계됨.
수정 후 out_stops.md의 상위 10개 순위가 바뀜(3·4위 교체).
```

```
viz(hourly): 요일 유형별 시간대 이용 비율 차트 추가
```

```
refactor(trend): 이상치 탐지 함수를 모듈로 분리

결과 변경 없음 (out_trend.md 동일 확인).
```

```
docs: README에 커밋 메시지 작성 규칙 추가
```
